# Launcher dependencies - the app itself, NOT the staging-inference stack
# (that is launcher/vision/requirements.txt, deliberately a separate venv).
#
# EXACT PINS, ON PURPOSE.
#
# These were `>=` until 2026-08-17, which meant every installer build resolved
# whatever happened to be newest that day. Two builds a month apart could ship
# different libraries while both claiming to be the same version of WormScan -
# which is not a defensible position for software that produces figures.
#
# The versions below are the set the 2026.08.17 installer shipped and that was
# exercised end to end on a clean machine. Bumping one is now a deliberate act
# with a commit attached, which is the whole point.
#
# To upgrade: change a pin, rebuild, re-run a known plate set, and diff the
# Excel against the previous run before believing it. `pip list --outdated`
# inside launcher/.venv shows what has moved.
#
# Note this pins only the top level. Transitive dependencies still float -
# `tables` alone pulls in blosc2, pydantic, httpx and rich. Every build records
# the COMPLETE resolved set in _wheels-manifest.txt inside the installation, so
# any build remains forensically traceable even where a transitive version is
# not fixed here.
